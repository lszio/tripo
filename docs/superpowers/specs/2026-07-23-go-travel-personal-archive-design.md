# Go Travel 个人旅行档案设计

## 产品定位

Go Travel 是一个单账号、长期累积的个人旅行记录工具，而非单次旅行攻略站。用户可持续建立任意数量的旅行档案；每趟旅行是一个独立子档案，包含出发前攻略和旅行中的真实记录。

## 信息架构

### 1. 我的旅行（首页）

- 以旅行封面卡片展示全部旅行，不限制时间范围或数量。
- 每张卡片显示目的地、旅行日期、状态（计划中 / 旅行中 / 已归档）、攻略完成度和记录数量。
- 支持按年份、目的地和状态筛选；提供全局足迹地图及搜索入口。
- 新建旅行首先创建一个空旅行档案，再逐步编辑攻略或记录。

### 2. 旅行攻略（单次旅行内页）

- 为单次旅行的默认视图，以天为单位组织高度可视化路书。
- 每天包含按时间排序的自由内容行程卡片；卡片内容由用户自行组织，可是路书、清单、地点、交通、图片、提醒或任意文字组合。
- 拖动卡片可调整计划日期或时段，仅改变攻略中的计划位置。
- 地图与路线随当前日和行程卡片同步展示。

### 3. 旅行记录（同一旅行的第二模式）

- 在同一旅行内从攻略模式切换至记录模式，而非创建一份分离的记录文档。
- 界面并列显示“攻略列”和“记录列”：攻略列显示进入记录时冻结的原始计划；记录列显示实际发生的图文、时间和地点。
- 记录卡可关联攻略卡，或标记为临时新增。
- 计划与实际分别保留：实际拖动/调整不会覆盖原攻略；系统生成可复盘的差异。

### 4. 旅行记录（全局页面）

- 仍以旅行卡片聚合所有旅行，但进入卡片后优先展示该旅行的完整真实记录。
- 每条记录可跳转至关联的攻略卡；未产生实录的旅行显示空记录状态和“开启记录”动作。

## 旅行卡片与状态

### 旅行状态

- `planned`：仅有攻略或尚未出发。
- `active`：已开启记录模式，旅途中持续新增实录。
- `archived`：旅行结束，以记录回顾为主要入口。

### 攻略卡片

- 内容没有固定格式。用户可在卡片中自由组合富文本、地点、交通、图片、清单、链接和个人提醒。
- 唯一的记录校准对象是卡片所在的计划日期；时间、地点等内容均为可选信息。
- 在攻略模式中可拖动卡片至其他日期或时段；每次变动只更新其计划位置。
- 进入记录模式后，对应的攻略版本变为只读快照，不能直接编辑。
- 用户如需修改攻略，必须从冻结版本复制出新的攻略副本；该副本可编辑，但不改变已开始记录的旅行对照基线。

### 记录卡片

- 固定字段：实际日、实际时间、文字、照片、实际地点、心情/标签。
- 可选 `planCardId` 关联一张攻略卡。
- 状态为 `completed`、`adjusted`、`skipped` 或 `added`。
- 关联卡片后，实际发生位置由记录卡保存；原攻略卡仍留在原计划位置。

## 核心交互规则

1. 攻略模式的拖动只调整攻略；不生成实际记录。
2. 用户点击“开启记录”后，系统冻结当前攻略为记录对照快照，并将旅行状态改为 `active`。
3. 记录模式允许新增记录、编辑记录，或将记录关联到攻略卡；冻结攻略只读。
4. 记录卡跨日拖动只更新实际日期/时间；不会移动攻略快照中的卡片。
5. 关联攻略卡的记录跨日时，系统标记为 `adjusted`；同日完成时可标记 `completed`。
6. 删除记录只删除真实记录，不回滚或删除攻略快照。
7. 用户可由冻结攻略复制出可编辑的攻略副本，用于形成新的计划版本；已有记录仍仅关联原快照。
8. 复盘由计划卡与记录卡的关系自动生成，不作为用户必须维护的第三套数据。

## 视觉方向

- 采用 Behance 式编辑型作品集气质：克制、留白充分、图片与内容优先、低装饰。
- 以暖白或浅灰纸张为主画布，配合墨黑文字与一个低饱和自然色作为强调色；状态颜色仅用于语义提示。
- 首页旅行卡采用高质量封面比例、大标题与稀疏元信息；不堆砌统计、边框和阴影。
- 攻略与记录以编辑画布般的轻卡片呈现，使用细边线和极浅层次，避免仪表盘式密集组件。
- 字体、间距、圆角和动效使用统一设计令牌；正文保证可读对比、键盘焦点与移动端触控尺寸。

## 旅行主题与攻略风格

- 产品外壳（首页、全局记录页、导航、交互控件）保持统一、轻量和克制，确保长期档案浏览体验一致。
- 每趟旅行的攻略可选择独立的“旅行主题”，它决定该旅行攻略内页的排版叙事、封面比例、色彩、字体层级、卡片形态和地图呈现，而不改变记录数据结构。
- 主题不是简单换色，而是可复用的攻略叙事模板。第一版提供三类：
  - `editorial`：杂志/摄影作品集式，大图、留白、章节化叙事，适合日本城市漫游。
  - `routebook`：地图与路线主导，日程节点清晰，适合自驾、徒步或城市间移动。
  - `archive`：图文档案与时间线主导，强调收藏、清单和细节，适合多城市长线旅行。
- 每次旅行只能启用一个攻略主题；切换主题不会改变攻略卡、记录卡、日期关系或已冻结的记录对照快照。
- 记录模式始终使用统一的双列记录工作台，以保证跨旅行记录的一致性；主题只影响左侧只读攻略快照的视觉展示与该旅行封面。
- 用户可在尚未开启记录的旅行中更换主题；开启记录后，当前主题随攻略快照冻结。复制攻略副本时可为新版本选择新主题。

## 第一版边界

- 仅一个本地账号及本地浏览器数据持久化。
- 不实现真实登录、多人协作、分享、评论、路线服务或第三方地图密钥。
- 支持多个旅行卡、全局旅行/记录入口、单旅行攻略模式、记录模式、图文记录和计划/实际关联。
- 示例奥匈旅行保留为其中一张可编辑的演示卡，并明确标识为虚构数据。

## 数据模型调整

```ts
type Travel = {
  id: string;
  title: string;
  cover: CoverTheme;
  status: "planned" | "active" | "archived";
  editablePlan: PlanVersion;
  recordingPlanSnapshot?: PlanVersion;
  records: RecordCard[];
};

type PlanVersion = { id: string; copiedFromId?: string; days: PlannedDay[] };
type ContentBlock = { id: string; kind: "text" | "place" | "image" | "checklist" | "link" | "embed"; value: unknown };

type PlanCard = {
  id: string;
  plannedDayId: string;
  plannedTime?: string;
  blocks: ContentBlock[];
};

type RecordCard = {
  id: string;
  actualDayId: string;
  actualTime: string;
  planCardId?: string;
  status: "completed" | "adjusted" | "skipped" | "added";
  content: string;
  photoUrls: string[];
  actualPlace?: Place;
};
```

## 验证标准

- 首页可浏览至少三张独立旅行卡，且能进入其攻略或记录入口。
- 攻略卡跨日拖动后仅攻略顺序改变。
- 记录卡可关联攻略卡，跨日记录不改变攻略原位置。
- 全局记录页仅展示有实录的旅行摘要，并能跳回该旅行攻略。
- 刷新页面后旅行、卡片位置和记录关联保持不变。
